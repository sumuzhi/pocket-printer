# 服务不做任何图像处理

## Status

accepted

## Context

打印机对成片有硬性要求：1200×1800 的 JPEG，不超过 2048KB。一个自然的想法是让
服务端负责缩放、裁剪、压缩，把各种尺寸的图片都"修正"到合规。

## Decision

**服务端只接受已经完全符合要求的成片，不做任何转换。**

它只做三件事：暂存字节、送印、报告打印机状态。

- 尺寸不对 → 不检查（打印机自己会处理，或打印结果不符预期）
- 不是 JPEG → **拒绝**（明确的文件头检查）
- 超过 2048KB → **明确报错**，不静默降质

## Considered Options

- **服务端缩放裁剪**：用户可以直接丢原图进来，更省事。但那样"打印的就是你看到的"
  这条保证会失效——调用方看到的预览与服务端实际打印的可能是两张不同的图。
  本项目的前身正是在这里踩过坑（预览与实际不符，浪费相纸）。
- **超限时自动降质**：能让请求总是成功，但用户不会知道画质被降低了。
  静默降质正是"印出来和预览不符"的根源。

## Consequences

- 调用方负责渲染成片。本项目不提供渲染功能（前身有，但被有意剥离——
  图像处理与送印是两件事，混在一起会让服务承担它不该承担的复杂度）。
- 错误是响亮的：超过上限返回 413 并说明当前大小与上限，而不是悄悄处理掉。
- 服务因此很小：约 1000 行，无图像处理依赖（不需要 Pillow/sharp 之类）。
