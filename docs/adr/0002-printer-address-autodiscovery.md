# 打印机地址自动发现，而非要求用户填写 MAC

## Status

accepted

## Context

早期实现把打印机地址硬编码为常量。这对作者可用，对任何其他人不可用——
他们 clone 下来只会连到一台不存在的设备。

让用户自己查 MAC 也不理想：「怎么找到我打印机的蓝牙地址」对普通用户是道坎，
而且不同系统显示方式不同。

## Decision

**启动时自动发现**：枚举已配对设备，按名称可能性排序，逐个尝试连接确认。

- 原生模块提供 `pairedDevices()`，返回系统已知的设备（含名称与配对状态）
- 排序依据名称关键词（`printer` / `打印` / `米家` / `xiaomi` / `hannto`）
- 逐个尝试 `openRFCOMMChannelSync` 确认——**连错设备不会写入任何数据、不会打印**，
  因此探测是安全的
- 仍支持 `--address <MAC>` 与 `PRINTER_ADDRESS` 环境变量覆盖

### 两个实现细节（都踩过坑）

**1. 复用探测成功的连接，不要关闭后重连。**
最初的实现是「探测连接 → 关闭 → 重新连接」，结果握手失败（`未收到 SERVER_HELLO_DH`）。
隔离测试显示直接连接 860ms 就成功——打印机需要时间从第一次通道恢复。
改为复用探测时建立的连接后正常。

这个缺陷只在走发现流程时出现，**而发现流程正是用户的默认路径**。

**2. 名称匹配只用于排序，不用于判定。**
设备名可以任意修改，因此不能仅凭名字断定"这就是打印机"。
真正的判定是能否打开 RFCOMM 通道并完成握手。

## Consequences

- 用户零配置即可使用。
- 枚举是同步的，约 17ms（实测），对启动无影响。
- 若打印机被重命名且名字不含关键词，仍会被尝试（只是排序靠后），
  因此不会因为改名而找不到。
